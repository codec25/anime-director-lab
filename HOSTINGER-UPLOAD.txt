Director UX:
- Main Director is intentionally organized into four stages: Direct, Perform, Review, Finish.
- Direct contains prompt/shot creation plus World/Scene Memory.
- Perform contains Cast + Voices and the same shot cards so Dialogue / Precision passes remain contextual.
- Review contains Continuity Review + Sound Design.
- Finish contains the Director Timeline + export.
- The former capability showcase and decorative memory cards were removed from the main page to avoid feature stacking; underlying APIs remain intact.

Live provider requirements:
- RUNWAY_API_KEY=...
- ANIME_DIRECTOR_BASE_URL must point to the public HTTPS app URL.
- ANIME_DIRECTOR_MOCK_MODE=0 for live generation.
- World/scene/shot image, video and audio references must be provider-fetchable public HTTPS URLs.
- Semantic roles available: character, environment, prop, style, motion, voice, sound, reference.
- Seedance 2.5 native reference generation is preferred when World Memory or shot references are active.
- Cast + Voices supports multiple recurring characters and per-character voice references.
- Precision performance uses Runway Act-Two (`/v1/character_performance`, model `act_two`) one speaking character per pass.
- Scene Continuity Review stores human checks plus deterministic metadata warnings.
- Sound Design stores Scene Bed, Music Cue and timed Shot SFX/Foley as editorial assets.

Final assembly / FFmpeg:
- Timeline stores shot order, selected takes, trims, cut/crossfade intent and separate dialogue/ambience/music/SFX mix rules.
- JSON manifest export always works.
- Server MP4 render is enabled only when FFmpeg is executable by PHP.
- Full renderer normalizes picture to the project orientation, applies trims, hard cuts or stored crossfades, and renders H.264/AAC.
- Dialogue, Scene Bed, Music and SFX are mixed as separate buses.
- Scene Bed / Music can loop across their scene ranges; SFX use their saved shot-relative timing.
- Dialogue audio is placed in turn order within each shot when no explicit line timecode exists.
- Music and ambience are sidechain-ducked under dialogue, then the final mix is limited and master fades are applied.
- FFprobe is used when available to measure generated audio duration; safe editorial fallbacks are used otherwise.
- Generated takes/audio must exist locally under the app storage for server rendering.
